chatgpt.com · SQLite WAL mode

In SQLite's WAL (Write-Ahead Logging) mode, changes do not overwrite the main database file directly. Instead, transactions append new committed pages to a separate .wal file.

1When a read transaction starts, SQLite remembers the last committed frame in the WAL. That end mark fixes which changes the reader can see.

1Spoken2:14 PM
wait so the reader doesn't even touch or lock the main db file, it just grabs an integer index in memory and walks the log for changes before that number?

That end mark freezes the reader's view to a point-in-time snapshot. Writers keep appending newer frames to the end of the log:

-- Writer appends frames 42, 43 to .wal
-- Active reader's end mark remains fixed at frame 40

Later comes checkpointing, which transfers committed WAL pages back into the main database file.

2A checkpoint can copy pages back into the database only as far as active readers allow. The WAL cannot be reset while readers still need its frames.

A reader on an older snapshot can limit checkpoint progress and prevent WAL reuse.

Readers and writers can usually run at the same time. A long-running reader can prevent WAL reuse, letting the file grow.

Below are notes I spoke out loud while reading…
Learn · 3 notes
Right

You've got the main idea: a long-running reader can prevent WAL reuse while writers keep appending. It doesn't normally block writes, though running out of disk space can make them fail.

Went off

The reader doesn't walk the whole log. For each page, it uses the WAL index to find the latest frame at or before its end mark. If there's no such frame, it reads the main database file. So it does touch that file, and it still takes read locks. Those locks usually don't block writers in WAL mode.

Missed

A reader doesn't necessarily stop the whole checkpoint. Pages can be copied back as far as active readers allow. Resetting the WAL requires a completed checkpoint and no readers still using its frames. When those conditions hold, a writer can reuse the WAL from the beginning…

Steering an agent

Answer the plan line by line. Then let it act.

A coding agent hands you a long plan. Replying with one message means addressing only what you remember. Instead, go through the plan, select specific parts, and react to each: agree, question, object, or change.

Paste your notes back with the Steer template. The agent answers, pushes back, and revises. Usually it takes two or three rounds to agree. Then it acts.

Five stacks. One per home-row key.

⌥J5 notes
⌥Kempty
⌥Lempty

You never create, name or delete them. Press a shortcut to switch between what you're reading.

Stacks are disposable. Export clears the stack, so each round starts empty.
