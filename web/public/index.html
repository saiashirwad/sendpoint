how does a CEK machine handle closures?

Closures in a CEK machine

A CEK machine is a small abstract machine for evaluating the lambda calculus. Its state has three parts: the control, which is the expression being evaluated; the environment, a map from variable names to values; and the continuation, which records what to do once the current expression produces a value.

Because the closure captures the environment at definition time, a CEK machine never substitutes. It extends the environment instead.

When the machine reaches a lambda expression it does not evaluate the body. It packages the lambda together with the current environment into a closure and treats that pair as the value. The body runs only when the closure is applied, and by then the machine may be somewhere else entirely.

Applying a closure

Application has two steps. First the machine evaluates the function position and pushes a frame onto the continuation that says "when you have the function, evaluate the argument". Then it evaluates the argument with a second frame that says "when you have the argument, apply".

The continuation is a separate stack of frames. Each frame records what to do with the value once it arrives.

Once both pieces are ready, the machine takes the closure's saved environment, binds the parameter to the argument value, and continues with the closure body in that extended environment. The caller's environment is not consulted at all, which is exactly what gives you lexical scope.

Variable lookup

Lookups walk the environment chain until they find the binding. In practice the chain stays short, because most closures are created in shallow scopes and are dropped as soon as their frame returns.

This is why the machine needs no substitution step. Every variable is resolved by lookup at the moment it is used, and the closure guarantees that the lookup happens in the environment the function was written in, not the one it was called from.

Why this matters

The same structure shows up in real interpreters. A closure in JavaScript or Scheme is the same pair of code plus captured environment, and a stack frame is the same kind of continuation frame. The CEK machine just makes the pieces explicit, which is why it is a useful model when you are trying to reason about scope, tail calls, or first-class continuations.
