I'm reading about the CEK machine and I'm stuck on closures. When a lambda becomes a value, what exactly gets captured—and which environment is used when that closure is applied? A tiny example would help.

In a CEK machine, a closure is essentially:

⟨λx.e, ρ⟩

where λx.e is the lambda itself, and ρ is the environment that was current when the lambda was evaluated.

That saved environment gives meaning to the lambda’s free variables. Conceptually, only free variables need to be captured; many presentations simply store the whole current environment because it is simpler.

For example:

let x = 10 in
  let f = λy. x + y in
    let x = 100 in
      f 3

When CEK reaches:

λy. x + y

the current environment contains:

ρ = { x ↦ 10 }

so the lambda becomes the closure:

⟨ λy. x + y, { x ↦ 10 } ⟩

Notice that y is not captured. It is bound by the lambda. x is free in the lambda body, so its meaning comes from the captured environment.

Later, at:

f 3

the current calling environment might contain:

{ x ↦ 100, f ↦ closure }

but CEK does not use that environment to evaluate the body of f.

Instead, when the closure is applied, CEK takes the closure's saved environment:

{ x ↦ 10 }

and extends it with the parameter binding:

{ x ↦ 10, y ↦ 3 }

Then it evaluates:

x + y

in that environment, producing:

10 + 3 = 13

So the key rule is:

Lambda creation: save the current environment.

Closure application: restore that saved environment and extend it with the argument binding.

Schematically:

⟨λx.e, ρ, k⟩  ⇒  closure (λx.e, ρ)

and applying

(λx.e, ρclosure) v

causes evaluation of

e

under

ρclosure[x ↦ v]

—not under the caller's environment.

This is exactly how the CEK machine implements lexical scoping.

⏺ apply is where a closure actually runs. The machine never
substitutes; it reuses the environment the closure captured.
case "apply": {
const { param, body, env } = frame.fn;
const next = env.extend(param, value);
return { control: body, env: next, kont: frame.kont };
}
That extend call is the whole trick. The caller's environment is dropped,
and the body continues in the closure's own, plus one binding.
Environments are linked frames, so extend is O(1).
Old environments stay valid, and closures can share them.
That is what makes scope lexical: a name resolves where the
function was written, not where it is called.
